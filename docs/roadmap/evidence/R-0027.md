# R-0027 Evidence: Uninstall Tanren Assets Without Deleting User Work

This document records evidence for [R-0027](../dag.json) — the CLI
uninstall flow that removes Tanren-generated repository assets while
preserving all user-owned files.

## Behavior coverage

R-0027 completes [B-0135](../../behaviors/B-0135-uninstall-tanren-assets-without-deleting-user-work.md):
*Uninstall Tanren assets without deleting user work*.

B-0135's canonical interface is `cli`. The feature file provides one
positive and three falsification witnesses, all targeting the CLI interface.

## Implemented command shape

The repo uninstall CLI surface is:

```text
tanren-cli uninstall [--repo <PATH>] [--confirm]
```

- `--repo` defaults to the current working directory.
- Omitting `--confirm` runs preview-only: reports what would be removed,
  preserved, or flagged with warnings, and performs no filesystem writes.
- Supplying `--confirm` applies the planned removal after preview output.

This matches the preview/apply contract documented in the delivery
architecture under Install Preview and Repo Uninstall.

## Manifest ownership rules

Uninstall reads `.tanren/install-manifest.toml` to determine which files
are Tanren-generated. Only files recorded as Tanren-owned in the manifest
are eligible for removal. Files not tracked by the manifest are
preserved regardless of path. This ensures:

- user-owned files (source code, tests, user-edited standards) are never
  deleted;
- stale manifest entries from a prior install version are handled
  gracefully (reported as warnings, not silently removed);
- empty directories left after generated file removal are cleaned up.

## Scope boundaries

Repo uninstall is a **local filesystem operation**. It does not:

- delete hosted account or project history;
- remove provider credentials, connections, or secrets;
- disconnect the project from the Tanren control plane (that is R-0021);
- remove the Tanren stack, containers, images, or database volumes;
- delete external tracker issues or pull requests.

These scope boundaries are enforced by the behavior feature: the
falsification witnesses explicitly verify that no account/project history
deletion path is exercised.

## Config and security implications

- Uninstall operates on local filesystem paths only — no credential,
  account, or provider deletion.
- Destructive actions require explicit `--confirm` flag; preview-only mode
  is the safe default.
- Absolute repository paths are redacted in command output.
- The manifest is a Tanren-owned install record; uninstall reads it but
  does not modify external state.
